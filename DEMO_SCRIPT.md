# Ninety-second browser demo

Use the exact production URL and commit that passed the browser checklist. Keep
the camera HUD, mode, and command status visible.

| Time | Action and line |
| --- | --- |
| 0–12s | Open the public HTTPS site. Say: “Signal is a hand controller and programmable command layer that runs entirely in your browser.” Click Start Signal and allow the camera. |
| 12–30s | In Control mode, move the virtual pointer with an index pose, quick-pinch once, then demonstrate held vertical scroll and horizontal zoom. Show FPS and latency. |
| 30–48s | Switch to Commands. Hold One through the progress indicator, release, then show that it fires once and rearms only after the pose changes. |
| 48–68s | Open the Fist editor. Generate the prefilled public-URL, wait, and speech plan; review and save it. Prepare the navigation tab with the explicit button. |
| 68–82s | Hold Fist and show the reviewed browser plan execute. If the optional provider is unavailable, point out the labeled deterministic fallback. |
| 82–90s | Show builder/profile sharing. Say: “The same public page recognizes, controls, plans, and shares—without an install or native companion.” |

## Recovery cues

- Planner/API failure: choose the seeded validated plan; say “offline fallback.”
- Navigation popup blocked: click Prepare action tab before the gesture.
- Discord failure/unconfigured secret: show the in-app receipt labeled fallback.
- Screen recorder failure: use the natural-language Fist flow.
- C shape instability before the demo: run one calibration capture; do not
  pretend fixture mode is live.
- Public profile failure: show local export/import while keeping the landing
  page available.
- Unsafe or unstable input: click Stop Signal, reframe the camera, then start
  again.
